# Shreyash Meshram - Portfolio

A detailed single-page portfolio for **Shreyash Meshram**, a **Full-Stack & AI Engineer** based in Nottingham, UK. The site presents Shreyash's profile, education, internships, technical toolkit, selected projects, project case study, resume links, and contact information in a polished editorial interface.

This repository is intentionally lightweight: there is no build step, package manager, or bundler. `Portfolio.html` loads React 18, ReactDOM, and Babel Standalone from CDNs, then mounts modular JSX files from `src/`.

## Featured Case Study

The portfolio includes a standalone ZenSpend case study at:

```text
case-studies/zenspend.html
```

The case study explains the design and engineering decisions behind ZenSpend, including:

- Why financial transaction data should stay local.
- The constraint of no outbound calls for inference.
- A local architecture using FastAPI, Ollama, Llama, Postgres, pgvector, and React.
- The ingest -> embed -> store -> retrieve flow.
- Why SQL handles arithmetic while the LLM handles classification, summarization, and query-template selection.
- Reported case-study metrics:
  - 94% categorization accuracy on an 18-month statement set.
  - Approximately 180ms median chat-to-answer latency on an M2 Pro.
  - 0 outbound network calls during normal use.
- Lessons learned around charting, prompt versioning, and making charge explanations more visible.

## Application Features

### Editorial Hero

The hero section uses large Fraunces typography, staggered reveal animations, role/location metadata, and clear calls to view work or get in touch.

### About + Toolkit

The about section explains Shreyash's engineering style and uses `PORTFOLIO.skills` to render categorized technology groups.

### Project Catalog

The projects section renders equalized project cards from `PORTFOLIO.projects`. Cards are keyboard-focusable and open a right-side detail drawer.

### Project Detail Drawer

Each project can be expanded without leaving the page. The drawer shows:

- Project number.
- Title and description.
- Highlights when available.
- Stack chips.
- Repository link.
- Case study link where present.

### Experience + Education Timeline

The experience section displays work and education side-by-side on desktop, collapsing into a single column on narrower screens.

### Command Palette

The command palette opens with `Cmd+K` on macOS or `Ctrl+K` elsewhere. It supports:

- Jumping to page sections.
- Opening project detail views.
- Toggling theme.
- Copying the email address.
- Opening GitHub, LinkedIn, and CV links.

### Theme Support

The site supports light and dark themes through `html[data-theme="dark"]`. Theme preference is saved to `localStorage` under `portfolio_theme`.

### Scroll Progress

A fixed top progress bar tracks reading position across the page.

### Tweaks Panel

The floating tweaks panel supports live edits for:

- Density: comfortable or tight section spacing.
- Typography: serif + mono, all-serif, or all-mono.
- Accent colors for light and dark themes.
- Theme switching.

The tweak defaults live in the `TWEAK_DEFAULTS` block inside `src/app.jsx`.

### Print Styling

`src/styles/print.css` forces a clean light theme, hides navigation and overlays, removes visual flourishes, and compacts sections for print output.

## Running Locally

Because this portfolio is static, any local static server works.

```sh
python3 -m http.server 8000
```

Then open:

```text
http://localhost:8000/Portfolio.html
```

Alternative:

```sh
npx serve .
```

Then open the URL printed by `serve` and navigate to `Portfolio.html`.

## Editing Content

Most content changes should happen in:

```text
src/data/portfolio.jsx
```

That file controls:

- Name, role, location, email, GitHub, LinkedIn, and resume path.
- Tagline and introduction.
- About paragraphs.
- Work experience roles, outcomes, and skills.
- Education institutions, degrees, periods, locations, and coursework.
- Skill categories and items.
- Project cards, highlights, stacks, links, and case-study links.

The rendering components are intentionally data-driven. In most cases, adding a new project or changing a role requires editing only the `PORTFOLIO` object.

### Adding a Project

Add a new object to `PORTFOLIO.projects`:

```jsx
{
  n: "18",
  title: "Project Name",
  blurb: "Short project summary.",
  highlights: [
    "Outcome or technical highlight",
    "Another highlight",
  ],
  stack: ["React", "FastAPI", "PostgreSQL"],
  href: "https://github.com/shreyuu/project-name",
  caseStudy: "case-studies/project-name.html",
}
```

`caseStudy` is optional. If it exists, the project drawer shows a case-study button.

### Adding Experience

Add a new object to `PORTFOLIO.experience`:

```jsx
{
  role: "Role Title",
  company: "Company Name",
  period: "Month YYYY - Month YYYY",

  blurb: "Short description of the role.",
  outcomes: [
```

## Implementation Notes

- The project does not use npm, Vite, Next.js, or a bundler.
- JSX is transpiled in the browser by Babel Standalone.
- Script order in `Portfolio.html` matters.
- Shared functions/components must be assigned to `window` because each Babel script has its own scope.
- `src/data/portfolio.jsx` must load before components and sections that read `window.PORTFOLIO`.
- `src/app.jsx` must load last because it mounts the app with `ReactDOM.createRoot`.
- Theme state is stored in `localStorage`.
- Command palette and project drawer manage body scroll locking when open.
- Reduced-motion users get animation suppression through `prefers-reduced-motion`.
- Print output hides navigation, command palette, tweaks panel, grain overlay, and visual chrome.
